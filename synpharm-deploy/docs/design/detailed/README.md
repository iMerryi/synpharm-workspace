## 3. 一句话结论（每份文档的要点）

| 文档 | 一句话 |
|---|---|
| **01** | 33 张表落地；确立 5 条全局规则：审计列规则、唯一键不含 `deleted` 的语义、双轨去重键、权重归一化、生成列实现"一主靶点/一口袋"不变式 |
| **02** | 79 个端点的契约；**归属校验失败一律 404**（不 403）；排行榜必须回传 `weightsSnapshot` + `redistributed` 让用户看见"哪些没算、权重去哪了" |
| **03** | 事务边界总表（红线 R5）；**MQ 一律 `afterCommit`**；唯一键 1062 必须归一化为业务错误码；能力探测把"未部署"在点击前就暴露 |
| **04** | P0 是能力矩阵端点（不先做，`available` 只能靠静态种子）；P1 是 RDKit 端点（**引擎已在镜像里**）；**Q4 校准工件协议**让回灌真正可生效、可回滚、可复现 |
| **05** | Q1/Q2/Q4/Q6/Q7 已闭环；Q3（大分子生成）建议**先规则式后生成式**；Q5 建议**归档表替代分区**（MySQL 分区与唯一键有硬冲突） |
| **06** | 服务收敛（design+asset+platform → `synpharm-core`）已落地；需求分析（八块基线 + 冻结快照）已落地；生成 S0~S9 与编辑 E0~E7 的设计已定、待实施 |
| **07** | 决策阶段只读证据包，不读候选当前状态；**技术性淘汰与业务性否决分两层**（`filter_reason` 补 `stage`）；证据包只装引用不装意见；风险接受逐候选逐点且 `must_verify` 项不可接受；决策与报告审批分离（报告引用 `decision_id`） |
| **08** | 靶点仓库 = 不可变来源/批次 + 可审核标准数据 + 兼容现有查询投影；先接 UniProt/PDB/AlphaFold DB，保留许可、结构版本与清洗证据 |
| **09** | 22 个数据集分 P0/P1/P2；清洗按 C0~C5 分级，活性类必须 C1~C4+C5，基准类 C5 强制；同时列明“绝不做的清洗”与许可核验项 |
| **10** | 生成阶段**以代码为准**：S1 未实现、S3/S9 是规则实现、S4 同步执行、缓存未启用；硬约束判定补「只有上限时回退 `thresholdMax`」，软约束目录只在 `must_pass` 时硬淘汰 |

```powershell
docker cp d:\synpharm-workspace\synpharm-backend\sql synpharm-dev-mysql:/tmp/allsql
# 00_ 建库（无默认库）→ 01_~38_（带 --database，等同 docker-entrypoint 行为）
# 再跑一遍 11_~38_ 验证幂等（应 28/28 OK）
```
