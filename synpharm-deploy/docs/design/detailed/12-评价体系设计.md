# 评价体系设计（原「分子预测」四页合并）

> 版本 v1.0 · 2026-11-03 · 状态：✅ 已实施并实测
> 代码位置：`synpharm-frontend/src/views/EvaluationSystem.vue`、`EvaluationRecords.vue`、
> `src/components/evaluation/*`、`synpharm-core/.../EvaluationCatalogController.java`、
> `CandidatePredictionController.java`、`sql/50_candidate_prediction.sql`

---

## 1. 为什么改

改之前侧栏是一组「分子预测」，下面挂四个页面：

| 页面 | 路由 | 内部已经是什么 |
|---|---|---|
| 仪表盘 | `/dashboard` | 页签：最近任务 / 最近结果 / 统计指标 |
| 预测中心 | `/predict` | 模式：单次 / 批量 / **预测历史** |
| 预测结果 | `/results` | 卡片网格 + 筛选 |
| 任务管理 | `/tasks` | 状态页签列表 |

问题不在样式，在**定位**：

1. **名字把手段当成了产品线**。分子预测（DTI/PPI/DDI）是一次具体计算，不是产品线。
   用户真正的诉求是「我这条分子值不值得往下走」，那不是一次预测能回答的。
2. **四页互相重复**。仪表盘的两个页签等于结果页 + 任务页；预测中心里的「预测历史」
   又是一个结果列表。同一份数据三处入口，改一处口径就要改三处。
3. **只回答「跑完了吗」，不回答「评什么、用什么评、评得准不准」**。体系缺了头尾。

---

## 2. 范围界定

**评价体系 = 指标口径 + 执行入口 + 记录留痕 + 结果回流。**

```
指标（评什么）
  ↓
执行入口（单次 / 批量，用什么评）
  ↓
记录（评价结果 / 评价任务，评得怎么样）
  ↓
回流（结论挂到设计域的候选上）
```

**明确不做的三件事**：

| 不做 | 原因 |
|---|---|
| 综合评价分 / 排序推荐 | 合成一个分数需要目的函数（权重、阈值），那属于项目基线，不属于评价体系。评价只陈列原值 |
| 结构生成 / 衍生 | 那是候选生成的职责，混进来会让「评价」变成「再造一个分子」 |
| 把预测域数据复制一份到设计域 | 复制那天起就有两个真相。设计域只存「结论属于哪个候选」，数值仍回预测域取 |

## 3. 信息架构

侧栏只留两项（用户选定）：

```
评价体系
  评价工作台   /evaluation            概览 | 单次评价 | 批量评价 | 指标 | 能力边界
  评价记录     /evaluation/records    评价结果 | 评价任务 | 结果对比
```

拆两项而不是一项的理由：**做评价**和**看结果**是两种动作。混在一页，
「我只是想查一条历史结果」也要先跨过一张发起表单。

### 3.1 页签与 `?tab=` 双向同步

页签与 `?tab=` 双向绑定，且用 `router.replace` 而不是 `push` ——
否则「后退」会在页签之间反复横跳。深链 `/evaluation?tab=metrics` 直接落到指标页；
候选项评估页的「送进评价体系」也靠它带 `candidateId` 跳进来。

### 3.2 旧地址一律重定向

| 旧地址 | 去向 |
|---|---|
| `/dashboard` | `/evaluation?tab=overview` |
| `/predict` | `/evaluation?tab=single`（保留原有 query） |
| `/results` | `/evaluation/records?tab=records` |
| `/tasks` | `/evaluation/records?tab=tasks` |

`/result/:id`（结果详情）、`/tasks/:id`（任务详情）、`/visualization`（3D）保持原样：
它们是**详情页**，本来就不该出现在一级导航里。

`views/Dashboard.vue` / `Predict.vue` / `Results.vue` / `Tasks.vue` 已删除，逻辑搬进
`components/evaluation/` 下的面板组件，避免两份真相。

> 需要注意的一处陷阱：侧栏「评价工作台」必须 `exact: true`。
> `/evaluation/records` 以 `/evaluation` 开头，按前缀匹配会让两项同时点亮。

## 4. 指标目录（评什么）

数据源是 `metric_definition` 表（24 条），接口 `GET /api/evaluation/metrics`。

- 网关新增 `core-evaluation` 路由（`/api/evaluation/**` → core）。刻意不并进
  `/api/design/**`：指标口径是评价体系的公共契约，不是某个项目的私有配置。
- **前端不硬编码指标清单**。写死一份就要为改一个指标发一次前端版本，且两份清单迟早对不上。

### 4.1 卡片上必须出现的字段

| 字段 | 为什么不能省 |
|---|---|
| `metricName` + `metricCode` | 中文名给人看，码给日志/接口对账 |
| `better` | `HIGHER` / `LOWER` / `NONE`。`NONE` 表示「只做约束判定，不参与打分」 |
| `weight` | `0` 是「仅展示」，不是「权重很小」 |
| `appliesTo` | 空数组 = 不限制分子形式；否则列出 `ANTIBODY` / `BISPECIFIC` 等 |
| `minValue` / `maxValue` | 归一化区间，解释「分数是怎么被压到 0~1 的」 |
| `remark` | 口径坑：例如「复用 KAN-MoDTI（靶点不得写死）」「受 1323 条白名单边界限制」 |
| `enabled` | 存在但未启用的指标要显式标出来 |

### 4.2 两条口径必须写在页面上

1. **权重之和不要求等于 100%**。综合分按「本次实际算出来的指标」的权重重归一化。
   实测当前权重合计 1.92 —— 页面上直接写出来，不假装是 1.00。
2. **算不出来 ≠ 0**。缺失的指标进 `missingMetrics`，不填 0。
   `LogP = 0` 和「LogP 算不出」在决策阶段含义完全不同。

## 5. 能力边界（用什么评、边界在哪）

三个模型的输入/输出是**契约说明**，写在 `BoundaryPanel.vue` 里；DDI 白名单是**真实数据**，
必须现取 `GET /api/predict/ddi/drugs`（实测 1323 条）。

| 模型 | 输入格式 | 边界 |
|---|---|---|
| DTI | `SMILES,靶点` | 靶点可填 UniProt ID 或 PDB 号，后端嗅探取序列；不认识的靶点直接拒绝，不拿近似蛋白顶替 |
| PPI | `蛋白序列A,蛋白序列B` | 只认序列，不认蛋白名/基因名 —— 名称到序列有歧义，猜错不报错只会静默算别的蛋白 |
| DDI | `药物A,药物B` | 转导式模型，只能预测训练图内的药物；SMILES 先转 DrugBank ID，转不出来即不在白名单 |

白名单之外不「尽量猜」：与其返回一个看起来像结论的数字，不如在提交前就说「不支持」。

## 6. 评价记录（评得怎么样）

| 页签 | 数据 | 要点 |
|---|---|---|
| 评价结果 | `GET /api/results` | 搜索 / 置信度筛选 / 排序都在前端做，避免「筛选」与「翻页」互相打架 |
| 评价任务 | `GET /api/tasks` | 任务回答「跑完了没有」，结果回答「结论是什么」，两处都要留 |
| 结果对比 | 同上，前端多选 | 最多 4 条并排；只比原值，**不做综合排名** |

对比表列头带结果编号（`EGFR · #9`）：同一靶点下会有多条结果，
只写靶点名会出现两列一模一样。

## 7. 与设计项目打通（结果回流）

### 7.1 表

`candidate_prediction`（`sql/50_candidate_prediction.sql`）：
`project_id` / `candidate_id` / `user_id` / `algo_type` / `target_id` / `target_name` /
`ligand_smiles` / `binding_affinity` / `confidence_score` / `confidence_level` /
`interactions`(JSON) / `predict_result_id` / `dataset_info`(JSON) / `note` / 审计列。

**为什么不复用 `evaluation_result`**：那张表挂在 `evaluation_run` 下，跑一次评估会批量覆盖
候选的指标集；而预测是「一次一条、可重复、带模型版本」的外部结论。
混在一起会出现「重跑一次理化评估把上次预测的亲和力冲掉」。

### 7.2 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/design/candidates/{id}/predictions` | 挂接一条结论 |
| GET | `/api/design/candidates/{id}/predictions` | 新→旧列表 |
| DELETE | `/api/design/candidates/{id}/predictions/{predictionId}` | 解除挂接（逻辑删除） |

三条纪律：

1. **幂等**：同一 `predictResultId` 重复挂接返回已有记录，不报 409。
   用户点两次「回写」不该得到两条，也不该以为失败 —— 结果已经在候选上了。
2. **不重算、不解释**：数值来自预测服务，服务端只做格式与归属校验。
   在设计域重算等于承认「两个预测器」，结论打架时无从判断谁对。
3. **越权一律 404**：`CANDIDATE_NOT_FOUND`，不用 403 —— 403 等于告诉对方「这个 id 存在」。

### 7.3 界面路径

1. 候选评估页（`/design/candidates/{id}/evaluation`）→ 右上「送进评价体系」
   → `/evaluation?tab=single&candidateId=…&projectId=…&candidateName=…&smiles=…`
2. 单次评价页出现来源横幅，SMILES 预填；跑完后「回写候选」按钮出现
3. 回到候选评估页，「外部预测」页签列出结论（类型 / 靶点 / 亲和力 / 置信度 / 来源结果 / 时间 / 解除挂接）

`ligandSmiles` 未提供时后端回落取候选自身的 `smiles` —— 结构不由前端回传。

## 8. 验收

`e2e-evaluation.ps1`（21 项断言）+ 浏览器探针（24 + 9 项）：

| 断言组 | 内容 |
|---|---|
| 侧栏 | 出现「评价体系」组，两项，旧的「分子预测」消失 |
| 工作台 | 5 个页签；概览 4 张统计卡；指标 24 张卡按 10 个 category 分组且显示权重 |
| 能力边界 | 3 个模型卡；DDI 白名单条数可读 |
| 记录 | 3 个页签；任务 5 个状态筛选项；选 2 条后出现 8 行对比表 |
| 重定向 | `/dashboard` `/predict` `/results` `/tasks` 四者落点正确 |
| 深链 | `?tab=metrics` 直接落到指标页 |
| 回流 | 挂接 / 幂等 / 列表 / JSON 往返 / 数值往返 / 非法 algoType 400 / 越权 404 / 解除 |
| 控制台 | 零 JS 错误 |

回归：原 13 套 e2e 共 389 项断言全绿（14 套合计 410 项）。
